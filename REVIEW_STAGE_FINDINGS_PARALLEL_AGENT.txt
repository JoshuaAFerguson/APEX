## Code Quality Issues (Detailed Findings)

### ISSUE 1: Gap Replacement Logic Uses Non-Global Regex
FILE: ParallelAgentTerminalView.tsx:153
CODE: return baseClasses.replace(/gap-\d+/, gapClass)
SEVERITY: MEDIUM
TYPE: Bug Risk - Fragile String Manipulation

DETAILS:
The regex pattern /gap-\d+/ without the 'g' flag will only replace the FIRST occurrence
of a gap class. While current configs only have one trailing 'gap-2' so this works,
it's fragile and will fail if configs ever have multiple gap classes.

IMPACT: Medium - Works currently but fragile. If configs are extended with multiple gap classes,
this will silently fail to replace all gaps.

FIX: Use /gap-\d+/g flag or redesign to not include hardcoded gaps in grid configs

---

### ISSUE 2: DOM Query Selector Lacks Input Validation
FILE: ParallelAgentTerminalView.tsx:174-175
CODE: `[data-testid="${testId}"] [data-panel-id="${panelId}"]`
SEVERITY: MEDIUM
TYPE: Security - CSS Selector Injection

DETAILS:
The testId and panelId values are directly interpolated into CSS selectors without escaping.
If either value contains CSS special characters (e.g., '[', ']', '#', '.', ':', spaces),
the selector will break or match incorrectly.

ATTACK EXAMPLE:
testId = "parallel[1]" → selector becomes [data-testid="parallel[1]"] (INVALID CSS)
panelId = "panel:active" → selector with pseudo-class could match wrong elements

IMPACT: Medium - Could cause focus to fail or focus wrong element. Potential for
unintended side effects in UI state.

FIX: Escape special characters in selector strings OR use safer DOM query methods:
- Use CSS.escape() for escaping
- Or use multiple querySelector calls with simple selectors
- Or use getAttribute() with Array.from(querySelectorAll('*')) for safer matching
