Issue #1: Error Information Leakage
File: npm-registry-utils.ts
Lines: 284-298
Severity: MEDIUM
Category: Security / Information Disclosure

Problem: Error messages returned to callers contain unfiltered exception details
that may expose sensitive system information.

Code:
  catch (error) {
    return {
      error: error instanceof Error ? error.message : 'Unknown error occurred'
    };
  }

Risk: Stack traces, file paths, and system details could be exposed.

Fix: Sanitize error messages before returning:
  const errorMessage = 'Failed to check version';  // Safe generic message
  if (error instanceof Error) {
    console.debug('Version check error:', error); // Log internally
    if (error.message.includes('timeout')) {
      errorMessage = 'Request timeout';
    }
  }

File: npm-registry-utils.ts
Lines: 224-231, 278-280
Severity: LOW
Category: Concurrency / Performance

Problem: Multiple concurrent requests for the same package make redundant
network calls instead of waiting for the in-flight request to complete.

Impact: Unnecessary network traffic, not a correctness issue.
