       - Doesn't count message structure (role, timestamp)

       Example: "你好" (Chinese "hello")
       - Estimated: ceil(2/4) = 1 token
       - Actual: 2-3 tokens (underestimate by 50%+)

    C) GREEDY REMOVAL (Line 410):
       while (...) {
         const removed = this.context.messages.shift();  // Always oldest
       }

       Doesn't consider message importance. Critical early context lost first.

    D) INTEGER TRUNCATION (Line 412):

         estimatedTokens -= Math.ceil(removed.content.length / 4);
       }

       Due to rounding, estimatedTokens may be inaccurate after removal.
       Loop exits prematurely while still over limit.

    E) METADATA NOT COUNTED (Line 403):
       Token calculation only uses m.content.length.
       Ignores metadata serialization overhead.

    FIX: Implement accurate token estimation and smarter pruning strategy.

ConversationManager.ts:97 - String normalization insufficient - MEDIUM

    zero-width characters, or HTML entities.

    CODE:
    const normalized = response.toLowerCase().trim();

    VULNERABILITIES:

       Input: "y​es" (contains U+200B zero-width space)
       Result: "y​es" (still contains ZWS!)
       Doesn't match 'yes'

    2. Unicode decomposition:
       Input: "ỹés" (combining characters)
       Result: Unchanged (doesn't decompose)
       Doesn't match 'yes'

    3. Homograph attacks:
       Input: "уes" (Cyrillic 'у' instead of Latin 'u')
       Result: Still doesn't match 'yes'
       Could be used to bypass confirmation

    4. HTML entities:
       Input: "&#x2019;" (right single quote entity)
       Result: Unchanged (not unescaped)

    FIX: Add normalize('NFKD'), remove zero-width chars, unescape HTML entities.
